# SettleUp — Development Log

A factual record of the order in which the project was built and verified. It records work
and decisions only; it does not describe meetings or feedback that did not happen.

## Phase 1 — Requirements, scope, architecture, schema

* Fixed the scope from the project brief: auth, groups, equal/custom expenses, balances,
  greedy settlements, recorded repayments, dashboard. Excluded: payments, invitations, OAuth,
  percentage splits.
* Decided on integer paise for all money (BIGINT in PostgreSQL, `int` in Python, string
  parsing in JavaScript).
* Designed six tables (`users`, `groups`, `group_members`, `expenses`, `expense_splits`,
  `settlements`) with FK/UNIQUE/CHECK constraints and targeted indexes.
* Chose a simple layered backend: routers → dependencies → services → models.

## Phase 2 — Backend foundation

* `config.py` (pydantic-settings), `database.py` (engine, session, `get_db`).
* SQLAlchemy 2 models with constraints and relationships.
* Alembic initialised; the initial migration was autogenerated, reviewed and renamed
  `0001_create_initial_schema.py`; applied to a local PostgreSQL 16 server.
* Authentication: bcrypt hashing, JWT (PyJWT), `get_current_user` dependency.
* Environment note: on this Windows machine the project path was long enough to break DLL
  loading inside the virtual environment, so the development venv was created in a short path.

## Phase 3 — Core features

* Groups and members, including admin-only actions, leave/remove with zero-balance rule and
  admin promotion.
* Expenses with equal (deterministic remainder) and custom splits; payer/admin-only edit and
  delete.
* Balance service (four GROUP BY queries) and the greedy settlement algorithm as a pure
  function.
* Settlement recording with validation under `SELECT ... FOR UPDATE`.

## Phase 4 — Dashboard, filters, errors

* Dashboard endpoint (totals, per-group balances, recent expenses, category and monthly
  summaries, my suggestions).
* Expense filters (category, member, date range) and pagination.
* Global handlers for integrity errors and unexpected errors.

## Phase 5 — Frontend

* Vite + React + Tailwind project; Axios client with token interceptors; auth context;
  protected routes; layouts; 14 screens; reusable UI components; `ExpenseForm` with live
  split preview.
* Pinned exact package versions.

## Phase 6 — Testing and fixes

* Backend: pytest suite against a real PostgreSQL test database built by the migration —
  96 tests passed on the first full run; one more (a documented counter-example where greedy
  is not optimal, found by brute-force search) was added → 97.
* Frontend: Vitest + Testing Library — 13 tests.
* Fixes made during this phase: Starlette test-client deprecation (switched to `httpx2`);
  npm peer-dependency conflict (compatible versions pinned); charts not rendering in
  background tabs (animations disabled); stray scrollbar on the group tab bar; 422 responses
  echoing submitted passwords (custom validation handler + test); a mis-named algorithm test.

## Phase 7 — Verification and documentation

* Ran the whole stack locally, exercised every page in a browser, captured 16 screenshots
  with Playwright + Edge.
* Ran the four-roommates API walkthrough against the live server and recorded the responses
  and database rows used in Chapter 21 of the guide.
* Captured the real SQL emitted by SQLAlchemy for Chapter 11.
* Wrote the README, test report and the complete technical guide (Markdown + PDF).

## Phase 8 — Repository preparation

* Initialised a local Git repository with `main` and the `backend/*`, `frontend/*`,
  `feature/*` branch convention documented in the README.
* Published to GitHub at github.com/sarvesh-s-g/settleup.
